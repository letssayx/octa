# Object Definitions & Framework

This specification details the components comprising the Privacy-First "Work Done" Engine. The system relies on a hybrid execution strategy to ensure robust capabilities while strictly enforcing client-side data privacy.

## Object Details

| Component | Object / Technology | Privacy Role & Functionality |
| :--- | :--- | :--- |
| **Simple Logic Generator** | WebLLM (In-Browser Gemma-2-2b / Llama-3-8b) | Handles simple drafting, natural language interactions, and basic local logic. Prompts and data handled by WebLLM never leave the browser. |
| **Complex Logic Generator** | Backend Qwen2.5-Coder via Ollama & FastAPI | Hosted on the SaaS cloud. Receives ONLY metadata (e.g., table schemas) and plain-text intents to generate advanced SQL or Python code. No raw user data is ever transmitted here. |
| **Computation Engine** | DuckDB-WASM / Pyodide | Performs math, aggregations, and data manipulation directly on local sales/CRM data in client RAM. Executes the SQL/Python generated by Qwen2.5-Coder. |
| **Data Grid & UI** | FortuneSheet / Dify-style UI Components | Provides a familiar embedded Excel/Spreadsheet experience for ad-hoc user analysis and acts as the workflow orchestrator. |
| **Public Data Connector** | FastAPI & TimescaleDB | Secure, read-only API gateway streaming public data (e.g., market ticks, generic vendor lists) for the client engine to analyze alongside private local data. |
| **Automation Hub (Local)** | Browser Hooks / URL Schemes | Utilizes `wa.me` for WhatsApp and `mailto:` for emails. Executes communications entirely via the user's local clients, avoiding centralized automation servers or external APIs. |
| **Grounded Memory** | IndexedDB / Local Storage | Employs `MEM_SAVE` and `MEM_LOAD` patterns. Stores user preferences (e.g., target margins, default thresholds), reminders, and "Hisaab" data persistently on the device only. |

## Execution Framework

### The "OpenClaw" Paradigm
By adopting this model, the SaaS platform provides the high-performance "Claw" (the algorithms, UI frameworks, code-generation services, and public datasets) while the client provides the "Subject" (the raw, sensitive data).

1.  **Data Ingestion:** User loads a CSV/Excel into the frontend. Data is loaded into DuckDB-WASM memory.
2.  **Metadata Extraction:** The frontend analyzes the file and extracts non-sensitive schema data (column names, data types).
3.  **Code Generation Request:** The user types a query (e.g., "Show me top clients by margin"). The frontend sends the query text + the extracted schema to the FastAPI backend.
4.  **Code Generation:** The backend Ollama (Qwen2.5-Coder) generates the precise SQL query.
5.  **Local Execution:** The generated SQL is sent back to the browser and executed by DuckDB-WASM against the local, sensitive data.
6.  **Results & Actions:** The results are displayed in FortuneSheet. If an action is requested (e.g., "Email these clients"), the frontend generates `mailto:` links to open the user's local email client.

### Grounded Memory Implementation
The application will utilize a memory management system to learn from the user while respecting privacy:
- **`MEM_SAVE`:** When a user dictates a preference, the frontend captures this state and writes it locally to browser storage (IndexedDB) as a settings file (e.g., `user.md` style JSON payload).
- **`MEM_LOAD`:** Upon application startup or specific workflow triggers, these local settings are read and injected into the frontend state or used to condition the metadata sent to the Qwen2.5-Coder backend (e.g., appending "Assume a default margin of 10%" to the prompt).
